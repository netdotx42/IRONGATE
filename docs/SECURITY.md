# Security and scoring

IRONGATE performs passive configuration observations, not vulnerability discovery, exploitation, authenticated crawling or proof of overall security. There are no paid security APIs and no AI integration.

## Network boundary

- Targets must be HTTP/HTTPS public hostnames. Default scheme is HTTPS. Embedded credentials, whitespace, backslashes, nonstandard ports, local names, all IP literals, ambiguous WHATWG IP encodings and internal suffixes are rejected.
- Every hop resolves DNS with a 2.5-second timeout. Any nonpublic address in an answer set rejects the destination. Loopback, RFC1918, link-local, CGNAT, multicast, reserved/documentation ranges, unique-local IPv6, mapped IPv6, and the Azure platform address are blocked.
- A validated IP is pinned into the Node HTTP request's lookup callback with an explicit address family. SNI/Host remain the target hostname. Agent reuse is disabled, TLS certificate trust/hostname checks remain enabled, and no environment proxy is deliberately used.
- Every redirect repeats validation. There are at most three followed redirects; HTTPS downgrade redirects are rejected.
- Only HEAD requests are sent. Response bodies are never consumed; sockets are closed after headers. Header size is capped at 16 KiB. Per-request timeout is at most five seconds and scan deadline is 16 seconds, including redirect handling. A preliminary DNS lookup is also bounded.
- HEAD 405/501 responses make header policies Not Tested. No GET fallback or body retrieval is implemented. Results reflect the scanner's vantage point and may differ from a browser, another location or an authenticated session.

The tests cover DNS pinning and revalidation with controlled request mocks. A raw external-network smoke attempt in the build environment failed DNS resolution, so a real external scan is not claimed as validated.

## Application boundary

Cookie-based Supabase SSR sessions use Secure cookies in production and SameSite=Lax. Client-side Supabase authentication requires JavaScript-readable auth cookies; these are not an HttpOnly-only BFF session design. Authorization always calls the hosted `getUser()` check server-side and uses RLS for reads. Proxy refresh is not the authorization boundary. Sensitive operations do not trust client-side state, user metadata or a cookie's unverified user object.

Mutations require an exact Origin match. JSON request bodies are streamed with an 8 KiB cap. Zod validates API structures and IDs. Database writes use Supabase query builders and bound RPC parameters. Errors return safe fixed codes. Untrusted header values, DNS strings and report values are encoded before rendering; exported HTML and email explicitly escape content.

Anonymous website scans have a 10/minute IP limit. Authenticated writes/scans share 20/minute IP and user limits; reads have separate 60/minute IP and user limits. These are database-atomic fixed-window counters. Production assumes Vercel's trusted forwarding headers; a different ingress needs its own trusted IP configuration. Missing database limits fail closed. Eight global scan leases expire after 45 seconds if interrupted.

Security response headers include HSTS, nosniff, frame denial, a restrictive referrer policy, restricted permissions and CSP. The CSP permits inline scripts/styles for the Next.js/shadcn rendering path; strict nonce-based script CSP is not implemented. There are no third-party analytics, fonts, scripts, password requests or trackers.

## Database and ownership

RLS protects every public table. Users can SELECT their own application records; direct application writes and privileged function execution are revoked from anon/authenticated. Server code checks ownership before any resource write. Composite foreign keys prevent cross-user domain/scan or domain/monitor references. User deletion cascades through all associated records.

DNS verification tokens use 32 random bytes generated by pgcrypto. Tokens are exposed only to their owning user and compared to the exact TXT value at `_irongate.<hostname>`. Verification is valid for 90 days. Monitor enrollment, updates and dispatcher selection independently enforce current verification. Pausing/deletion remains possible without renewed ownership. Tokens are retained for re-verification; keep the TXT record in place.

Privileged RPCs have pinned `search_path` and explicit EXECUTE revocations. Auth triggers are narrowly scoped to profile/preferences creation. Application service credentials must never be shipped to the browser. Service-key compromise remains privileged compromise and requires immediate key rotation.

## Deterministic scoring v1.0.0

| WebShield check | Weight |
| --- | ---: |
| Public DNS resolution | 5 |
| HTTPS response availability | 25 |
| Trusted TLS and hostname | 25 |
| Certificate remaining lifetime | 20 |
| HTTP upgrades to HTTPS | 15 |
| Observable cookie attributes | 10 |

| HeaderGuard check | Weight |
| --- | ---: |
| Content-Security-Policy | 25 |
| Strict-Transport-Security | 20 |
| X-Content-Type-Options | 15 |
| Referrer-Policy | 10 |
| Permissions-Policy | 10 |
| Framing protection | 20 |

Configured earns full weight, Needs Review half, Missing zero. Not Tested and Not Applicable are excluded. Score is rounded to the nearest integer from earned/applicable weight. With no applicable checks, score and grade are null. A ≥90; B ≥80; C ≥70; D ≥60; otherwise F. Negative checks of weight 20+ are classified critical, lower weights warning; unknown is informational. These are configuration priorities, not exploitation severity ratings.

TLS validation runs on each HTTPS hop. Expiry uses the minimum lifetime across observed HTTPS redirect certificates. If a certificate is invalid, validation is not disabled to retrieve it: the invalid TLS finding is reported and unobservable expiry is Not Tested. Session-cookie intent cannot be inferred from arbitrary cookies, so cookie recommendations explicitly require context.

Header quality uses conservative heuristics, not a full CSP/Permissions-Policy parser. Broad or inline/eval script policies need review; HSTS must contain a single parseable max-age of at least 180 days; nosniff must match; referrer policy must be recognized; permissions policy must show restrictions; enforcing frame-ancestors takes precedence over legacy X-Frame-Options. A policy passing heuristics does not prove the application is secure. Recommendations avoid unconditional preload/includeSubDomains or conflicting framing policies.

## Password privacy

zxcvbn loads only in KeyGuard. Passwords stay in component memory and are cleared on reset/unmount. No password enters a request, URL, storage, database, log or analytics. Generator uses Web Crypto, rejection sampling and a cryptographic shuffle; selected groups are present. Length is 12–64. The compact passphrase generator selects eight independent words from 128 words (56 bits before modifications); do not shorten it. Estimation assumes the displayed guessing model and cannot know server hashing, breaches or reuse.

## Reporting a problem

Contact the installation's configured support address. Include a UTC timestamp, tool and safe reproduction. Do not send passwords, session tokens or service credentials. Preserve incident evidence securely and rotate affected credentials when required.
